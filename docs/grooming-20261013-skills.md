## Findings and changes

1. **Generated Bonuses exceeded actual saturation.** Guarded Movement requested approximately 104% under default power intent, although `ShieldMath.movementMultiplier` stops improving at 100%. Legal stronger intent could publish several states beyond that boundary. Guard Readiness likewise exceeded the point where both supported vanilla timings stop improving: raise delay 5 to 1 ticks, and disable delay 100 to 20 ticks, giving an 80% meaningful ceiling. `NativeBonusMechanics.limit` now supplies factual ceilings before Bonus allocation/pricing. Swim Speed retains its native additive ceiling; Sneak Speed now uses the distinct `ADD_MULTIPLIED_BASE` headroom calculation. The ceiling and explanation are saved in the generated track. A longer hypothetical external shield disable is not evidence for additional purchasable ranks.

2. **Whole-tick shield savings suffered floating-point underdelivery.** Computing `ceil(100 * (1 - .43))` yields 58 ticks instead of the intended 57 because the intermediate value is 57.00000000000001. The shared runtime now subtracts saved ticks before applying the ceiling. The regression checks every whole percentage from 0 through 100, and checks that a percentage just short of the 20% raise-delay boundary does not receive an unearned tick.

3. **Audit coverage was not a per-state receipt.** `skillProgressionAudit` now emits `skillRankCoverage`, `bonusTierCoverage`, and `coverageSummary` in addition to its existing registry/runtime/layout information. Every published rank has essence family, tier, marginal/cumulative cost, prerequisites, requirements, activation/choice information, actual resolved parameters, declared native measurements, deltas from the previous published rank, parameter bounds and floor results. Every registered Bonus has every tier row, including unavailable and completed states; active endpoints include incremental/cumulative cost, applied progression, prior completed endpoint, floors, caps, route evidence and confidence. Named probes execute the shared shield arithmetic and native attribute sanitizers for guard movement/readiness, swimming, sneaking, max health (two HP per heart), and step height.

4. **Life Steal's measurement assumed a favorable attack count.** Its authored floor is one HP over a 20-HP target fight, with another half HP per purchased rank. The old measurement added `20 * baseHealingFraction + 40 * perHitHealingFraction`, equivalent to five equal four-damage chained hits. At the schema reference values, this claimed 1.6 HP while a legitimate one-hit kill healed only 0.8 HP. Current publication measures the same authored floors against `20 * baseHealingFraction`; optional chain gains remain extra. Focused tests exercise every published rank over one, two, four, five and twenty accepted hits, with continuous or broken chains. The runtime workstream also added native one-hit 20-damage and 200-damage overkill kills, with sufficient missing health and zero equipment healing amplification. This verifies actual damage attribution, healing, paid rank state and cleanup rather than assuming nominal damage is accepted.

5. **Saved outcome validation now has an explicit contract.** Fresh publication records `composition.native_outcome_contract=2`. Profiles without this marker retain historical contract 1 during validation, including its exact old Life Steal measurement; loading changes no saved parameter, rank, cost or transaction history. An explicit rebuild is required to receive the stricter minimum. The exhaustive audit uses current contract 2 and records both versions, so a historical profile can be honestly reported as below the new verified minimum without making ordinary loading rewrite or reject it. The compatibility test proves unchanged legacy roundtrip, rejects labeling old sub-floor values as contract 2, rejects unknown/fractional contracts, and confirms new generation-only Bonus ceilings do not reject an older uncapped track.

6. **Percentage-only damage endpoints could add less than one damage.** `NativeDamageBonusFloor` reads the candidate's physical baselines through the actual profile multiplier and rounding consumer. Melee includes every supported held profile (the hoe is the weakest first-party profile); ranged and magic use the exact profile gates in their runtime handlers. Every new completed endpoint must satisfy both the authored percentage floor and a one-point native base-damage increment with identical equipment. The conservative weakest powered context determines a percentage-point lower bound; insufficient nominal states are coalesced, never subdivided into filler. Units remain percentages. The melee attribute ceiling is also respected, and a profile with no usable native headroom fails with an explicit incompatibility rather than silently removing the Bonus. Probes compare previous/current endpoints on the same active-tier equipment; unarmed, Latent and fractured equipment do not activate these Bonuses, and equipment below the player's tier caps activation at its own tier. This reference is a fully charged, unmitigated attack; armor, invulnerability, critical hits and travel-dependent projectile damage are separate contexts.

7. **Custom shield timing could invalidate the default reference.** Final publication now reads the candidate's actual `minimumDisableTicks`, including human overrides. It saves that configuration and its factual native ceiling. In addition to the authored percentage floor, each endpoint must save at least one whole tick on the supported raise or disable timing. A 100-tick minimum disables all recovery improvement, so only real 5-to-1 raise-delay boundaries can supply meaningful states. Tests cover minimum values 1, 20, 99 and 100. Existing saved profiles remain exact until explicit rebuild.

8. **Draw/cast percentage increments can leave native cooldowns unchanged.** These two equipment handlers use `max(1, round(20 / actionsPerSecond))`; the shared method is now public for generation and diagnostics without changing runtime semantics. At a physical rate of ten per second, 10%, 15% and 20% additions all leave the same two-tick cooldown. New publication grants the first usable whole-tick boundary (34% here), even when that exceeds the nominal budget. Later states must satisfy both the authored percentage floor and at least one whole-tick saving against the previous completed endpoint on identical active-tier equipment. Sub-tick states coalesce; strong useful jumps remain intact. Placement can retain an earlier useful span when later physical gear already has a one-tick cooldown. If every supported tier is already saturated, generation reports the actual rates and incompatibility; it does not silently remove the track. Saved profiles are only inspected, never republished on ordinary loading. Audit rows now include this actual shared cooldown consumer.

9. **Other attributes have distinct native ceilings and units.** The shared limit policy now covers attack knockback and knockback resistance (additive fraction), maximum health (two HP per saved heart), both reach attributes (additive blocks), Luck (additive levels), and movement, mining and jump strength (multiplicative native base). Reach uses the lesser headroom so neither advertised range saturates before completion. Probes call the actual attribute sanitizers and report the expected native-unit increment. Full supported equipment applicability with no external modifier is the explicit reference; attribute measurements are not claims about every loadout, loot pool, block or terrain. Adversarial requests of one million saved units test bounded publication without weakening authored floors.

10. **Melee speed has a different native saturation from bow/caster timing.** Native `Player.attack` samples float readiness at `attackStrengthTicker + 0.5`; its damage factor is `0.2 + 0.8 * readiness²`. Equal full-charge tick counts can still provide a real partial-charge improvement, so bow-style rounding would reject useful melee states. At 40 attacks per second even ticker zero is fully charged; increases beyond this are ineffective despite the attribute's larger range. New melee publication uses each supported same-tier profile's rounded physical rate and applicability, preserves percentage floors, and stops or selects an earlier valid span at the actual gameplay ceiling. The shared equipment-state selector supplies placement and quantized first-floor search for both timing classes. Audit probes report fixed native charge-state changes, never invented attack uptime or DPS.

The expanded audit reports counts of declared-floor and named-native-probe failures separately, plus the number of states with native probes. First-rank rows include the actual configured unpurchased parameter and its delta while explicitly marking the effect inactive; a nonzero inactive default is not rewritten to zero. Null native-floor results mean no native probe, not success.

## Evidence boundaries and continuation

Coverage is exhaustive over the actual registries and published state lists; it is not an assertion that every gameplay trigger ran in a live world. Skill outcome rows call the actual resolved-parameter consumer but retain declared conditional contexts. Binary capability rows are explicitly marked as requiring native hook fixtures. Bonus probes run on the isolated audit classpath, not inside the target pack's loader; their named reference contexts cannot establish pack-specific uptime or external modifiers. Step probes use the recorded generated baseline. The matrix runner must attach actual loader fixture evidence separately.

Salvager's Craft also has equipment-dependent saturation: one-material or fractional ambiguous recipes cannot safely guarantee one recovered material, and very small eligible recipes may already saturate at the first rank. In particular, a proven two-material bill combined with guaranteed one-item recovery and a strict one-material loss must return exactly one item at every rank. No later native recovery gain is possible in that context. Allowing a stochastic zero payout would violate the authored guarantee, so this remains an explicit conditional incompatibility, not evidence that the later native floor passed. Candidate 6 uses proven recipe materials, bounds recovery by consumed inputs, and rejects the custom recycle action when a material return cannot be established, even if ordinary disenchanting could return XP. The native salvage fixture passes 100,029 checks on both loaders. That receipt verifies proof/conservation and eligible recovery behavior; it does not turn saturated small bills into successful later-rank progression.
