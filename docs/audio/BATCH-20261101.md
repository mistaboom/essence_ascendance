## Listening direction and beam design

Channeling is the distinctive musical centerpiece. Ordinary physical actions reuse suitable Minecraft sounds. Menus use short tactile ticks and friendly expressive chirps; combat effects stay brief and legible; ascendance earns a ceremonial original flourish. The Nintendo, Zelda, Star Wars droid, and other game references supplied by the user describe character and behavior. No samples or melodies from those works are used in the original candidate recipes.

The beam family combines original items 2 and 5. Crucible-to-player and Crucible-to-Infuser receive distinct but compatible chord sequences. Zero active pylons supplies one foundational note; each active pylon adds one note, through the supported eight-pylon maximum and nine-note chord. The sound should resemble the sustained resonance of high-quality wind chimes with the initial strike removed. Upper notes gently leave and return at staggered intervals while the root remains comparatively stable. Sparse twinkling shares the pitch family. Additional notes should add richness without making the full structure proportionately louder. Both destinations and multiple nearby structures must remain compatible.

The eighteen individual state recipes are periodic 12-second bodies. The two 27.5-second build demonstrations reveal the nine successive states and are listening demonstrations, not runtime loop selections. Standalone beam and powered-flight listening previews present two periods with 650 ms fades at the outer boundaries only. Raw decoded eight-period fixtures remain separate: they do not hide joins with player restarts or boundary fades. Neither a good browser preview nor a passing decoded join test establishes native-engine loop acceptance.

2. **Use actual transfers for beam sources.** `AudioSources` currently includes Crucible dissolution, Infuser processing, and independent Focus hums. The new source roles must instead use `MachineVisualState.Crucible.playerStreams()` with positive actual rate and `transferringToInfuser()` for the second destination. `supplyingInfuser()` represents demand and must not substitute for actual transfer. Mere links, items, reservoir capacity, or idle pylon presence are not activity.
3. **Use authoritative active pylon membership.** `MachineVisualState.Crucible.activePylons()` already supplies the count. `EssenceCrucibleStructureService` selects linked, Focus-equipped pylons under the configured limit; runtime balance validation caps that limit at eight. Do not count arbitrary nearby pylons or reconstruct eligibility in audio. Changes should transition smoothly between compatible chord states.
4. **Avoid duplicate beam voices.** The existing private `channel.resonance` lease and public Crucible body can otherwise describe the same transfer twice. Use one shared source identity per Crucible/destination role and resolve listener ownership deliberately. `ChannelSessionsPayload.Link` has source/generation/reason/allocated/actual but no pylon count; loaded Crucible observer state already carries that count. Do not introduce an independent private hum, per-beam manager, or new heartbeat just for music.
5. **Extend shared composition, not gameplay.** Current `AudioCatalog.Profile` resolves one continuous body. Runtime note layering/count transitions require a reusable shared extension or count-specific mixes. Preserve shared lifecycle fades, admission, voice/storage bounds, pause, mute, range, reload, cleanup, and existing validity rules. Up to nine notes per source must not accidentally multiply the voice budget without review. The chord-building demonstration is not a ready-made substitute for a real live pylon transition.
6. **Add a committed Focus-install occurrence.** `EssencePylonBlockEntity.installOrSwapFocus` has a real mutation path after the Focus changes and inventory return is handled. It also returns `CONSUME` when the held Focus is identical, so generic success is not sufficient. Cover actual authorized hand/menu installation or replacement, not loading, visual snapshots, automation, or an unchanged interaction. The existing `machine.focus.body` identity describes a continuous body and must not be silently repurposed as an installation sound.
7. **Select native reuse with correct ownership.** Avoid layering Glaive contact or shield accents on already emitted native outcomes. Keep arrow shooter confirmation private and optional. Native totem reuse belongs to the initial rescue, not reform. Reference selection is not a runtime routing change.
8. **Mix approved originals at their authored pitch first.** Existing fallback policies include cast pitch 1.6, explosion 1.5, and denial 0.8. Do not silently apply those values to new unity-pitch custom contours or assume they are the desired retained-native settings. Adjust canonical shared policies only after review and actual game listening.
